# Evaluation

## 1. Цель оценки

Цель оценки — проверить работоспособность multi-agent системы, сравнить несколько локальных LLM и измерить основные характеристики работы системы.

В рамках минимальной версии проекта используются:

* функциональные тесты агентов;
* benchmark локальных моделей;
* измерение latency;
* наблюдаемость через Langfuse;
* проверка работы памяти между агентами.

---

## 2. Тестируемые модели

Для сравнения были выбраны три локальные модели, доступные через Ollama:

| Модель      |  Размер |
| ----------- | ------: |
| Qwen3:4b    | ~2.5 GB |
| Gemma3:4b   | ~3.3 GB |
| Llama3.2:3b | ~2.0 GB |

Все модели запускаются локально в контейнере Ollama.

---

## 3. Набор тестов

Для всех моделей использовались одинаковые запросы.

### Test 1 — объяснение понятия

Запрос:

```text
Объясни простыми словами, что такое производная.
Ответь на русском языке.
Дай короткое объяснение и один простой пример.
```

Проверяется:

* способность объяснить математическое понятие;
* корректность определения;
* наличие примера;
* соблюдение русского языка.

---

### Test 2 — генерация учебной задачи

Запрос:

```text
Создай одну учебную задачу по квадратным уравнениям.
Ответь на русском языке.
Укажи условие задачи и её сложность.
```

Проверяется:

* способность генерировать учебную задачу;
* соответствие теме;
* корректность математического задания;
* понятность формулировки.

---

### Test 3 — проверка ответа студента

Запрос:

```text
Проверь ответ студента.

Задача: x² - 10x + 16 = 0.
Ответ студента: x = 3 и x = 5.

Правильные корни: x = 2 и x = 8.

Скажи, правильный ли ответ студента,
и кратко объясни ошибку.
Ответь на русском языке.
```

Проверяется:

* определение правильности ответа;
* математическая корректность;
* обнаружение ошибки;
* объяснение ошибки.

---

## 4. Результаты benchmark

### Qwen3:4b

| Тест                      |        Время |
| ------------------------- | -----------: |
| Explain derivative        |     105.53 s |
| Generate quadratic task   |     271.70 s |
| Evaluate quadratic answer |      91.53 s |
| **Среднее**               | **156.25 s** |

Модель корректно выполнила математическую проверку и правильно определила корни квадратного уравнения.

Основной недостаток в проведённом тесте — высокая задержка генерации.

Qwen3 также может формировать внутреннее thinking/reasoning, поэтому в проекте используется очистка итогового ответа перед его передачей пользователю.

---

### Gemma3:4b

| Тест                      |      Время |
| ------------------------- | ---------: |
| Explain derivative        |    14.95 s |
| Generate quadratic task   |     6.06 s |
| Evaluate quadratic answer |     4.73 s |
| **Среднее**               | **8.58 s** |

Модель успешно объяснила производную и сгенерировала математическую задачу.

При проверке ответа студента модель правильно определила, что ответ неверен, однако объяснение ошибки получилось слишком коротким.

---

### Llama3.2:3b

| Тест                      |      Время |
| ------------------------- | ---------: |
| Explain derivative        |    11.83 s |
| Generate quadratic task   |     5.17 s |
| Evaluate quadratic answer |     3.38 s |
| **Среднее**               | **6.79 s** |

Модель показала минимальную задержку среди трёх протестированных моделей.

При этом в тесте генерации задачи была обнаружена математическая ошибка: модель указала, что у уравнения `x² + 5x + 6 = 0` одно решение, хотя у него два действительных корня.

Проверка неправильного ответа студента была выполнена корректно, но объяснение также получилось недостаточно подробным.

## 6. Memory evaluation

В системе реализована общая память на базе SQLite.

Память разделена на:

### Short-term memory

Хранится история сообщений текущей сессии:

* student_id;
* session_id;
* role;
* message content;
* agent;
* timestamp.

### Long-term memory

Хранятся:

* результаты assessment;
* оценки;
* прогресс по теме;
* обнаруженные ошибки;
* пользовательские факты.

---

## 7. Тест shared memory

Для проверки памяти использовался сценарий из нескольких этапов.

### Шаг 1

Assessment получает:

```text
Проверь мой ответ.
Уравнение x² - 10x + 16 = 0.
Я получил x = 3 и x = 5.
```

После оценки в памяти появляется:

```text
LEARNING PROGRESS:
- quadratic_equation: 0.0%

KNOWN MISTAKES:
- quadratic_equation:
  Assessment score: 0.0%
```

### Шаг 2

В другой сессии Tutor получает:

```text
Какие ошибки я недавно допускал?
```

с тем же:

```text
student_id = ivan
```

Tutor получает информацию из общей базы памяти и сообщает о предыдущей ошибке при решении квадратного уравнения.

Таким образом проверяется доступ двух разных агентов к общей долгосрочной памяти.

## 8. Langfuse

Langfuse используется для наблюдаемости работы системы.

Текущая интеграция выполняется на уровне Orchestrator.

Для каждого запроса создаётся observation:

```text
name = orchestrator
type = generation
model = router
```

В observation передаются:

* входной запрос;
* итоговый ответ;
* количество входных токенов;
* количество выходных токенов;
* имя выбранного агента;
* student_id;
* session_id.

Используются следующие основные параметры:

```text
input
output
usage_details.input
usage_details.output
metadata.agent
metadata.student_id
metadata.session_id
```

Это позволяет анализировать выполнение запросов и отслеживать взаимодействие Orchestrator с агентами.

---

## 9. Ограничения оценки

Проведённый benchmark является небольшим практическим тестом и не представляет собой полноценное научное исследование.

Ограничения:

1. Используется небольшая выборка из трёх тестов.
2. Оценивается ограниченное количество предметных сценариев.
3. Latency зависит от локального оборудования.
4. Качество генерации оценивается вручную по результатам тестов.
5. Один и тот же запрос может давать разные ответы при различных параметрах генерации.

Поэтому результаты используются как практическое сравнение моделей для данного прототипа, а не как универсальный рейтинг LLM.
